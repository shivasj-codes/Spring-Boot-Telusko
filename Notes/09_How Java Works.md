## 1. Why can't we directly run Java code?

When we write Java code such as:

```java
System.out.println("Hello World");
```

the computer does **not directly execute the Java source code**.

Java goes through multiple steps before we see the output.

The basic flow is:

```text
Java Source Code
       ↓
    Compiler
       ↓
   Bytecode
       ↓
      JVM
       ↓
    Output
```

---

# 2. What is JVM?

**JVM = Java Virtual Machine**

The JVM is responsible for **executing Java bytecode**.

You can think of it as the environment/machine that understands and runs Java bytecode.

### Important point

Your Java application does not directly run on the hardware.

The basic layers are:

```text
Java Application
       ↓
      JVM
       ↓
       OS
       ↓
    Hardware
```

For example:

```text
Java Application
       ↓
JVM
       ↓
Windows
       ↓
Laptop Hardware
```

Or:

```text
Java Application
       ↓
JVM
       ↓
Linux
       ↓
Server Hardware
```

---

# 3. Java Platform Independence

One of the important features of Java is:

> **Write Once, Run Anywhere (WORA)**

This means that Java code can run on different operating systems/platforms, provided the required Java runtime environment is available.

For example, you can develop an application on:

```text
Windows
```

and run the compiled application on:

```text
Linux
```

or:

```text
macOS
```

### Why?

Because Java source code is converted into **bytecode**.

The bytecode is not specific to Windows or Linux.

The JVM on each platform understands that bytecode.

```text
Java Code
    ↓
 Bytecode
    ↓
 ┌─────────────┐
 │             │
JVM           JVM
Windows       Linux
 │             │
 ↓             ↓
Run           Run
```

---

# 4. Is JVM Platform Independent?

There is an important distinction:

### Java Application

**Platform independent**

### JVM

**Platform dependent**

The JVM itself needs to be built for a particular operating system/platform.

For example:

```text
Windows → Windows JVM
Linux   → Linux JVM
macOS   → macOS JVM
```

So:

> **Java bytecode is platform independent, but the JVM implementation is platform dependent.**

This is what allows Java applications to run on different platforms.

# 5. Java Source Code

When we write Java code, we create a **Java source file**.

The extension is:

```text
.java
```

Example:

```text
Hello.java
```

Inside it, we can write:

```java
System.out.println("Hello World");
```

However, the JVM does not directly understand this source code.

The source code needs to be **compiled**.

# 6. Java Compiler

The Java compiler is called:

```text
javac
```

It means:

> Java Compiler

The compiler converts:

```text
Java Source Code
        ↓
      javac
        ↓
     Bytecode
```

For example:

```text
Hello.java
    ↓
  javac
    ↓
Hello.class
```

---

# 7. What is Bytecode?

**Bytecode** is the intermediate code generated by the Java compiler.

The JVM understands bytecode.

The bytecode is stored in a:

```text
.class
```

file.

For example:

```text
Hello.java
```

is the Java source file.

After compilation:

```text
Hello.class
```

is generated.

### Remember

| File     | Meaning                |
| -------- | ---------------------- |
| `.java`  | Java source code       |
| `.class` | Compiled Java bytecode |

# 9. Why do we need a `main()` method?

A Java project can contain many Java files.

For example:

```text
Project
 ├── Hello.java
 ├── Student.java
 ├── Employee.java
 ├── Calculator.java
 └── Test.java
```

The JVM needs to know **where execution should begin**.

Therefore, we provide a starting point.

That starting point is the:

```java
main()
```

method.

---

The standard main method signature is:

```java
public static void main(String[] args)
```

You should remember this signature.

### It contains:

```text
public
static
void
main
String[] args
```

The lesson explains that the JVM looks for this particular method signature when starting the application. 

We will learn the meaning of each keyword separately.

# 11. Meaning of the Main Method — Basic Understanding

For now, remember:

```java
public static void main(String[] args)
```

is the standard entry point for a Java application.

Example:

```java
public class Hello {

    public static void main(String[] args) {

        System.out.println("Hello World");

    }
}
```

Execution starts from:

```java
main()
```

# 12. Why do we need a Class?

Java is an **object-oriented programming language**.

Java code is organized using **classes**.

Therefore, our code needs to be inside a class.

Example:

```java
public class Hello {

    public static void main(String[] args) {

        System.out.println("Hello World");

    }
}
```

Here:

```java
public class Hello
```

is the class.

And:

```java
public static void main(String[] args)
```

is the main method.

Hello

For a `public` class, the file name should match the class name.

# 16. Compilation

Suppose our file is:

```text
Hello.java
```

We compile it using:

```cmd
javac Hello.java
```

The compiler generates:

```text
Hello.class
```

So:

```text
Hello.java
     ↓
   javac
     ↓
Hello.class
```

The `.class` file contains the **bytecode**.

---

# 17. Running the Java Program

After compilation, we need to run the bytecode.

We use:

```cmd
java Hello
```

Notice something important.

During compilation:

```cmd
javac Hello.java
```

we specify:

```text
Hello.java
```

But while running:

```cmd
java Hello
```

we specify:

```text
Hello
```

### Do NOT use:

```cmd
java Hello.class
```

The command uses the **class name**, not the `.class` filename.

# 22. JDK vs JRE vs JVM

This is one of the most important topics to remember.

| --------- | ------------------------ | ------------------------- |
| **JDK**   | Java Development Kit     | Develop Java applications |
| **JRE**   | Java Runtime Environment | Run Java applications     |

```text

```

> `javac` is a development tool; it is needed for compiling, not merely for running an already compiled application.

# 29. Quick Q&A for Revision

### Q1. What is JVM?

**Answer:** JVM stands for Java Virtual Machine. It executes Java bytecode.

### Q2. What is JRE?

**Answer:** JRE stands for Java Runtime Environment. It provides the environment required to run Java applications.

### Q3. What is JDK?

**Answer:** JDK stands for Java Development Kit. It is used by developers to develop Java applications.

### Q4. What is `javac`?

**Answer:** `javac` is the Java compiler. It converts `.java` source code into `.class` bytecode.

### Q5. What is bytecode?

**Answer:** Bytecode is the intermediate code generated by the Java compiler and executed by the JVM.

### Q6. What is the extension of Java source code?

**Answer:**

```text
.java
```

### Q7. What is the extension of compiled Java bytecode?

**Answer:**

```text
.class
```

### Q8. What is the standard entry point of a Java application?

**Answer:**

```java
public static void main(String[] args)
```

### Q9. Which command compiles Java code?

**Answer:**

```cmd
javac Hello.java
```

### Q10. Which command runs the compiled Java class?

**Answer:**

```cmd
java Hello
```

### Q11. Do we specify `.class` when running?

**Answer:** No.

Use:

```cmd
java Hello
```

not:

```cmd
java Hello.class
```

### Q12. Why is Java called platform independent?

**Answer:** Java source code is compiled into platform-independent bytecode, which can be executed by a JVM available for the target platform.

### Q13. Is JVM platform independent?

**Answer:** No. JVM implementations are platform dependent.

### Q14. What does WORA mean?

**Answer:** **Write Once, Run Anywhere.**

### Q15. Does every Java application need a `main()` method?

**Answer:** For the standard standalone application startup described in this lesson, the JVM looks for the `main()` method with the required signature.

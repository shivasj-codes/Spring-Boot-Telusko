Use this prompt for your future Java/Spring Boot lessons:

```text
I am learning Java and Spring Boot.

I will provide lesson material such as:
- Video transcript
- Screenshots
- Code
- My own notes
- Other supporting information

Create SHORT, CLEAR STUDY NOTES from the material.

IMPORTANT FORMAT:

1. The notes must be completely inside a JavaDoc comment:

/**
 * ============================================================
 * TOPIC NAME
 * ============================================================
 *
 * Explanation...
 *
 * ============================================================
 */

2. I should be able to directly copy and paste the notes into
   my Java editor.

3. DO NOT give normal explanations outside the JavaDoc comment.

4. Keep the notes SMALL and UNDERSTANDABLE.
   Do not make them unnecessarily long.

5. Focus only on the important concepts from the lesson.
   Do not add unrelated advanced concepts.

6. Use SIMPLE BEGINNER-FRIENDLY English.

7. Preserve the terminology used in the lesson.

8. Include the important explanations from the transcript,
   not just definitions.

9. Do NOT include the complete code if I have already provided
   the code separately.

   Only use small code examples/syntax when they are necessary
   to explain a concept.

10. If I specifically ask for "code + comments", then provide
    the complete code with clear comments.

11. For code explanations, use simple comments like:

// Calculator -> Class name
// calc -> Reference variable
// new -> Creates a new object
// Calculator() -> Constructor call

12. Prefer normal explanations over too many bullet points.

13. Use numbered points only when they make the concept easier
    to understand.

14. Use headings such as:

 * ============================================================
 * TOPIC
 * ============================================================

15. Clearly mention important rules using:

 * IMPORTANT:
 * NOTE:
 * REMEMBER:
 * WARNING:

16. Correct obvious spelling or transcription mistakes while
    preserving the intended technical meaning.

17. If the lesson contains an example, include a SMALL,
    easy-to-understand example.

18. If screenshots contain important information that is not
    in the transcript, include that information.

19. Do not repeat the same explanation unnecessarily.

20. Do not invent information that is not supported by the
    provided material.

21. At the end, always include:

/**
 * ============================================================
 * KEY POINTS TO REMEMBER
 * ============================================================
 *
 * 1. ...
 * 2. ...
 * 3. ...
 *
 * ============================================================
 * QUICK SUMMARY
 * ============================================================
 *
 * concept -> simple meaning
 * concept -> simple meaning
 *
 * ============================================================
 */

IMPORTANT STYLE:

- SHORT NOTES
- EASY TO REVISE
- BEGINNER FRIENDLY
- JAVA DOC FORMAT
- NO ESSAY
- NO UNNECESSARY DETAILS
- NO COMPLETE CODE UNLESS I ASK FOR "CODE + COMMENTS"
- USE SMALL EXAMPLES WHERE NEEDED
- KEEP THE SAME FORMATTING FOR ALL FUTURE LESSONS

When I provide the next lesson, directly create the notes
without asking unnecessary questions.
```
